# Фитстенд: опрос с учётом здоровья и 2–3 варианта велосипеда

Дата: 2026-11-04. Статус: черновик на просмотр. Источник: второй отзыв продавца (блоки «Спина», «Колени», «Шея, плечи, руки», «Амортизация», «Геометрия», «Сценарий», «Как использовать этот опросник»).

## 1. Зачем

Покупатели с травмами и ограничениями чаще всего ошибаются с выбором: берут спортивную посадку при грыже, стандартные шатуны при ограниченном сгибании колена, маленькую раму с высоко поднятым седлом. Продавец просит учитывать спину, колени, шею и руки и выдавать не один велосипед, а 2–3 варианта с разными компромиссами.

Цель: человек без травм проходит опрос как раньше (на один вопрос больше), человек с травмами отвечает только на вопросы о своих ограничениях, видит, что приложение учло, получает 2–3 варианта с оснасткой и предупреждениями и подбор размера с поправками посадки.

Ограничения:

- без брендов и цен; «дешевле» означает «проще устроен»;
- приложение не ставит диагнозов и не запрещает виды велосипедов — оно подсказывает и предупреждает;
- обязательный дисклеймер и совет обратиться к врачу после операций и травм;
- ответы хранятся только на устройстве; никакого сервера.

Не входит: разделение MTB на хардтейл и двухподвес как отдельные виды (подпроект A), аксессуары (подпроект B), реалистичные картинки (подпроект E).

## 2. Ход опроса

### 2.1 Вопросы

| Шаг | Идентификатор | Вопрос | Кому | Выбор |
|---|---|---|---|---|
| 1–6 | `q1`…`q6` | старые 6 вопросов без изменений | всем | один |
| 7 | `gate` | Есть ли у вас травмы или ограничения, которые нужно учесть? | всем | несколько |
| | `back1` | Есть ли у вас диагностированные проблемы со спиной? | `gate` ∋ `back` | несколько |
| | `back2` | Какая посадка была бы комфортнее для спины? | `gate` ∋ `back` | один |
| | экран «Спина» | объяснение | `gate` ∋ `back` | — |
| | `knee1` | Были ли травмы или операции на коленях или тазобедренных суставах? | `gate` ∋ `knees` | несколько |
| | `knee2` | Насколько комфортно вы переносите нагрузку на колено? | `gate` ∋ `knees` | один |
| | экран «Колени» | объяснение | `gate` ∋ `knees` | — |
| | `upper1` | Есть ли боль или ограничения в шее, плечах или запястьях? | `gate` ∋ `upper` | несколько |
| | экран «Шея и руки» | объяснение | `gate` ∋ `upper` | — |
| | `cushion` | Насколько важна для вас амортизация? | `gate` — не только `none` | один |

Ответы `gate`: `back` «Спина», `knees` «Колени и бёдра», `upper` «Шея, плечи, руки», `none` «Нет». Выбор `none` снимает остальные; выбор любого другого снимает `none`.

Тексты вопросов и ответов блоков — дословно из отзыва, кроме ответа `back2` «Могу tolerate лёгкий наклон…»: он становится «Готов(а) к лёгкому наклону, если есть амортизация».

Не задаются отдельно:

- «По какому покрытию вы планируете ездить?» — берётся из `q1` и `q4`. **Бездорожье** — `q1` = «В лесу, горах, по бездорожью» или `q4` ∈ {«корни, камни, грязь», «прыгаю и катаюсь агрессивно»};
- «Какой сценарий использования ближе?» — таблица продавца «сценарий + ограничение» реализована как эффекты ответов (раздел 3) и правила вариантов (раздел 4);
- «Готовы ли вы смотреть на параметры геометрии?» — вместо вопроса в результате всегда есть раскрывающийся раздел «Цифры геометрии» (раздел 5.2).

### 2.2 Шаги и адреса

`quizFlow(answers, content)` возвращает список шагов: `{kind:'q', id}` или `{kind:'explain', block}`. Адрес `#quiz/N` — шаг N этого списка (с 1). Наибольшая длина списка — 16 шагов; `parseRoute` принимает N от 1 до 16, остальное считает шагом 1. Если N больше длины текущего списка, открывается первый шаг без ответа.

Вопрос с выбором одного ответа — как сейчас: нажатие сохраняет ответ и ведёт дальше. Вопрос с выбором нескольких — ответы-переключатели и кнопка «Дальше», активная, когда выбран хотя бы один. Экран-объяснение — заголовок блока, 1–3 строки `explain` выбранных ответов этого блока и кнопка «Дальше».

Счётчик: «Вопрос N из M», где M — число шагов-вопросов в текущем списке; экраны-объяснения не нумеруются.

Если человек вернулся к `gate` и снял блок, ответы этого блока удаляются.

### 2.3 Дисклеймер

На шаге `gate` под ответами мелким текстом:

> Приложение не заменяет консультацию врача и профессионального байкфиттера. Ответы хранятся только на этом устройстве и никуда не отправляются.

## 3. Эффекты ответов

У каждого ответа блоков здоровья в `content.js` есть поля (все необязательные):

| Поле | Тип | Смысл |
|---|---|---|
| `pts` | `{вид: число}` | добавка к баллам видов, может быть отрицательной |
| `fit.upright` | градусы | спина вертикальнее |
| `fit.barUp` | мм | руль выше |
| `fit.crankMax` | мм | шатуны не длиннее |
| `fit.stepThrough` | да/нет | рама с низкой верхней трубой |
| `gear` | список | нужная оснастка (раздел 3.2) |
| `warn` | `{types:[вид…], text}` | предупреждение, если вариант этого вида |
| `explain` | строка | для экрана-объяснения блока |
| `reason` | строка | для «Почему» |
| `note` | строка | для «Что учесть» |
| `rehab` | да | включает совет врача |

Сложение: `upright` и `barUp` суммируются, `crankMax` берётся минимальный, `stepThrough` — если хоть один ответ его даёт, `gear` объединяется. Ограничения после сложения: `upright` ≤ 12, `barUp` ≤ 60, `crankMax` ≥ 145.

## 4. Результат: 2–3 варианта

`buildResult(answers, content)` возвращает:

```
{ complete, firstMissing?, scores, motor, variants: [Variant], reasons: [строка], notes: [строка], rehab: да/нет, health: {upright, barUp, crankMax, stepThrough} }
Variant = { kind: 'balance'|'comfort'|'simple', type, motor, gear: [id], fit: {upright, barUp, crankMax, stepThrough}, warn: [строка] }
```

Баллы = старые баллы `q1`…`q6` + `pts` ответов здоровья. Правила ничьей, мотор и совет про e-bike — как сейчас.

**Баланс:** победитель по баллам; `gear` — вся оснастка из ответов, плюс `stepThrough`, если его дала сумма `fit`, и `shortCranks`, если задан `crankMax`; `fit` — сумма поправок. Оснастка всегда в порядке таблицы 3.2.

**Максимальный комфорт:**

- при бездорожье — `mtb`, к оснастке «Баланса» добавляется `fullSusp`;
- если победитель `folding` — `folding`;
- иначе — первый вид в порядке `city`, `hybrid`, `gravel`, `mtb`, `road`, у которого баллы > 0 и не меньше 50 % баллов победителя;
- к оснастке добавляются `suspFork`, `suspPost`, `wideTyres`, `riseBar` (для `mtb` вилка и так есть); `fit` = поправки «Баланса» + `upright` 3 и `barUp` 20 (с теми же ограничениями);
- если вид и оснастка совпали с «Балансом», вариант не показывается.

**Проще и дешевле:** вид «Баланса»; из оснастки убираются `fullSusp`, `suspFork`, `suspPost`, добавляются `wideTyres`; `fit` как у «Баланса». Показывается, только если оснастка изменилась.

**Предупреждения:** `warn` выбранных ответов прикрепляется к каждому варианту, чей вид входит в `warn.types`.

**Причины:** сначала `reason` ответов здоровья (не больше 2), затем старые причины; всего не больше 4; строка про мотор — как сейчас.

**Заметки:** старые заметки, затем `note` ответов здоровья, затем совет про e-bike.

Человек без травм получает «Баланс» без оснастки и «Максимальный комфорт» с комфортной оснасткой — он показывается всегда, потому что оснастка отличается. «Проще и дешевле» у него не появляется: убирать нечего.

## 5. Экраны

### 5.1 Результат

Сверху вниз:

1. «Вам подойдёт» и название вида «Баланса» (+ «с мотором»).
2. Если `rehab` — заметная плашка: «Перед большими нагрузками посоветуйтесь со своим лечащим врачом или реабилитологом».
3. Карточки вариантов: подпись («Баланс», «Максимальный комфорт», «Проще и дешевле»), мини-схема с оснасткой, название вида, оснастка метками, жёлтые предупреждения, кнопка «Подобрать размер».
4. «Почему», «Что учесть».
5. Плюсы и минусы, «С чего начать» — для вида «Баланса».
6. «Цифры геометрии» — раскрывающийся раздел (5.2).
7. Дисклеймер: «Приложение не заменяет консультацию врача и профессионального байкфиттера. При серьёзных травмах и после операций окончательное решение лучше принимать вместе с ортопедом или реабилитологом и после примерки у специалиста.»
8. «Пройти заново», «Все виды».

Блок «Ещё подойдёт» убирается: его роль выполняют варианты.

### 5.2 Цифры геометрии

Таблица для «Баланса» под текущий рост из фитстенда, строки:

| Параметр | Значение | Что означает | Куда смотреть при травмах |
|---|---|---|---|
| Stack | мм подобранного размера | высота передней части | выше — для спины, шеи, вертикальной посадки |
| Reach | мм | длина от каретки до руля | короче — чтобы не тянуться и не перегружать поясницу |
| Длина шатунов | мм | радиус педалирования | короче — при коленях, ограничении сгибания, боли в спине |
| Высота руля | stack + проставки, мм | положение рук | выше — для шеи, плеч, запястий |
| Ширина шин | мм | поглощение неровностей | шире — для спины и суставов |
| Тип рамы | обычная / с низкой трубой | посадка и сход | низкая труба — после операций на ногах и тазе |

Под таблицей — предупреждение продавца: «Если взять раму меньше нужного и поднять седло, руль окажется слишком низко…».

### 5.3 Фитстенд

- «Подобрать размер» на карточке передаёт вид, мотор, `fit` и оснастку варианта.
- Вкладка «Посадка»: строка «Учтено здоровье: спина +6°, руль +30 мм, шатуны 155 мм, рама с низкой трубой» и переключатель «Учитывать» (по умолчанию включён). Строки нет, если поправок нет.
- Модель (`fit`) при включённых поправках:
  - угол спины: `alpha + upright` и при выборе размера, и при настройке кокпита — так размер подбирается по stack и reach, а не «меньше рама — выше седло»;
  - руль: цель для кистей выше на `barUp`;
  - шатуны: не длиннее `crankMax`;
  - норма угла спины в метриках сдвигается на `upright`;
  - у метрики «Длина шатунов» подсказка «укорочены по ответам о коленях», если `crankMax` сработал.
- Схема: `suspFork` — амортвилка на любом виде; `suspPost` — утолщение подседельного штыря; `wideTyres` — покрышка не уже 46 мм; `stepThrough` — верхняя труба опущена к нижней трети подседельной трубы.

### 5.4 Меню

Новый пункт «Стереть мои ответы»: после подтверждения удаляет ответы опроса и поправки посадки. Рост и пропорции остаются.

## 6. Сохранение

Ключ `fitstand:v1`. Поле `quiz` становится объектом `{v:2, a:{q1…q6: номер, gate: [id], back1: [номер], back2: номер, knee1: [номер], knee2: номер, upper1: [номер], cushion: номер}}`. Старое значение — массив из 6 номеров — переводится в `{v:2, a:{q1…q6}}`: пройденный опрос откроется на шаге 7. Новые поля состояния: `health` (`upright`, `barUp`, `crankMax`, `stepThrough`, `gear`) и `healthOn`. Всё проверяется при чтении; неверные значения отбрасываются.

## 8. Проверка

Автотесты (`node --test`):

- `quizFlow`: без травм — 7 шагов; `back` — +3 шага (2 вопроса и объяснение) и `cushion`; `back` + `knees` + `upper` — 16 шагов; снятие блока удаляет его ответы;
- `buildResult`: сложение и ограничения (`upright` 12, `barUp` 60, `crankMax` 145); `pts` здоровья меняют победителя; варианты 3/2/1 по правилам раздела 4; бездорожье даёт `fullSusp`; `warn` на нужном варианте; `rehab`; причины не больше 4, здоровье первым;
- перевод старого `quiz`-массива; отбрасывание повреждённого `quiz`, `health`;
- модель: без поправок — прежние эталоны; `upright` увеличивает угол спины; `barUp` поднимает руль; `crankMax` ограничивает шатуны;
