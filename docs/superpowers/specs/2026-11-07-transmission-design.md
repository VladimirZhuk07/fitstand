# Фитстенд: трансмиссия по четвёртому отзыву

Дата: 2026-11-07. Статус: на просмотр. Источник: четвёртый отзыв продавца, пункты про трансмиссию (R3–R5 в `info/Feedback 4/Требования по отзыву 4.md`, не в репозитории).
Это подзадача A. Подзадача B — сцена езды на главной (реалистичный велосипедист, своя езда под каждый вид) — отдельная спецификация после ответов продавца.

## 1. Зачем

Покупатель-новичок открывает «Узлы велосипеда → Трансмиссия» и находит:

1. Каждую деталь трансмиссии на своей странице: что это, виды, поломки, уход — по таблице из п. 3 — и где она на велосипеде (подсветка на схеме).
2. У четырёх готовых вариантов (одна скорость, планетарная втулка, 1×, 2×/3×) — кому подходит и для каких трасс.
3. В конце раздела — как пользоваться трансмиссией.

Ограничения: без брендов (тест `no brands`), тексты на русском, коротко и просто, тексты только в `content.js`. Живой рисунок и сцена езды на главной не меняются.

Не входит: сцена езды (подзадача B), картинки для деталей (на страницах деталей — схема, не фото).

## 2. Варианты трансмиссии (R4)

У каждого из четырёх `parts.drivetrain.variants` два новых поля, оба — непустые строки:

| Поле | Выводится как |
|---|---|
| `forWhom` | «Кому подходит: …» |
| `terrain` | «Для каких трасс: …» (уже выводится в `partView`) |

`partView` выводит `forWhom` строкой «Кому подходит» перед «Для каких трасс» — для любого узла, у которого поле есть.

## 3. Детали трансмиссии (R3)

Новое поле `parts.drivetrain.details` — массив из восьми деталей в этом порядке:

| `id` | `name` | Обязательные поля | Обязательные блоки `more` (заголовки) |
|---|---|---|---|
| `bb` | Каретка | `text`, `breaks`, `care` | — |
| `cranks` | Шатуны и звёзды | `text`, `kinds` | «Из чего делают», «Какие для каких целей» |
| `chain` | Цепь | `text`, `kinds`, `care` | — |
| `fd` | Передний переключатель | `text`, `how`, `breaks`, `care` | — |
| `rd` | Задний переключатель | `text`, `how`, `breaks`, `care` | — |
| `cassette` | Кассета / трещотка | `text`, `kinds` | «Под какие трассы», «Что надёжнее» |
| `shifters` | Манетки | `text`, `kinds` | «Манетка или велошифт» (таблица) |
| `cables` | Тросики и рубашки | `text` | «Как проводят тросики», «Какая проводка лучше» |

Форма детали:

```js
{ id, name, short,            // short ≤ 60 символов, для карточки
  text,                       // «Что это» — строка
  how,                        // «Как работает» — строка
  kinds: [{ name, text, pros, cons }],   // «Виды»: ≥ 2; pros и cons по 1–3 строки
  breaks: [{ name, text }],   // «Частые поломки и как их избежать»: ≥ 2; name — поломка, text — как избежать
  care: [строка],             // «Уход»: ≥ 2 пунктов
  more: [{ title, text | list | table }] }   // формат как у узлов
```

Необязательное поле может быть у любой детали (например, `how` у цепи) — выводится, если есть.

`shifters.kinds` содержит «Триггерные манетки» и «Велошифт (поворотная ручка)». Таблица «Манетка или велошифт» — заголовок `['', 'Манетка', 'Велошифт']`, не меньше четырёх строк сравнения.

**Педали** остаются узлом `parts.pedals`, в `details` их нет; ссылка на них — `parts.drivetrain.related = ['pedals']` (карточки связанных узлов после деталей). Изменения в узле:

- третий вариант `{ name: 'Комбинированные', … }` — с одной стороны платформа, с другой контакт; картинка `img/parts/pedals-2.webp` (см. п. 6);
- `pedals.more` — блок «Как подобрать педали» (список).

## 4. Как пользоваться трансмиссией (R5)

`parts.drivetrain.more` — ровно эти блоки в этом порядке, каждый — непустой список `list`:

1. «Как переключать на разных трассах»
2. «Как не испортить трансмиссию»
3. «Частые ошибки новичков»
4. «Как выбрать трансмиссию новичку»
5. «Уход за трансмиссией»

## 5. Страницы и адреса

**Адреса** (`parseRoute` в `guide.js`):

| Адрес | Результат |
|---|---|
| `#parts/drivetrain/chain` | `{ view: 'detail', part: 'drivetrain', id: 'chain' }` |
| `#parts/drivetrain/xyz` | `{ view: 'part', id: 'drivetrain' }` |
| `#parts/brakes/chain` (у узла нет `details`) | `{ view: 'part', id: 'brakes' }` |
| `#parts/xyz/chain` | `{ view: 'parts' }` |
| `#types/mtb/x`, любые адреса из 4+ частей | `{ view: 'fit' }`, как сейчас |

**Страница «Трансмиссия»:** схема, варианты, затем раздел «Детали» — карточки восьми деталей (`name`, `short`, ссылка `#parts/drivetrain/<id>`) и девятая карточка «Педали» → `#parts/pedals`; потом блоки `more`.

**Страница детали:** заголовок `name`, над ним мелко «Трансмиссия»; схема с подсветкой этой детали; `short` как вводная строка; разделы по порядку: «Что это», «Как работает», «Виды» (как варианты узла: название, текст, плюсы и минусы), «Частые поломки и как их избежать», «Уход», затем блоки `more`. Нет поля — нет раздела. «Назад» — как на остальных страницах справочника.

## 6. Схема (`draw.js`)

- `part(name, inner, d)`: у группы детали атрибут `data-d="<id>"`. Группа светится (`data-on`), если `highlight === name` или `highlight === name + ':' + d`.
- Трансмиссия рисуется подгруппами `data-part="drivetrain"` с `data-d`: `chain` (цепь), `cassette` (кассета), `cranks` (звезда и шатун), `bb` (каретка — кружок в центре). На живом рисунке и на всех статичных — тот же вид, что сейчас; меняется только группировка.
- Новый флаг `opts.details`: только при нём и только на статичном рисунке с цепью дорисовываются `rd` (задний переключатель под кассетой), `fd` (передний — пластина на подседельной трубе над звездой), `shifters` (манетка у грипа на руле), `cables` (тросик от руля вдоль нижней трубы к каретке и к заднему переключателю). Это группы `data-part="drivetrain"` верхнего уровня, чтобы подсветка работала существующим CSS.
- В справочнике: `bike(style, motor, hl, cls, details)` пишет `data-details="1"`; `drawBike` передаёт `details` в `bikeMarkup`. Флаг ставят страница «Трансмиссия» и страницы деталей.
- Подсветка детали на странице детали: `highlight = 'drivetrain:<id>'`.

## 7. Картинка комбинированных педалей

- В `tools/make-image-prompts.js` → `PARTS.pedals` третий английский промпт: педаль с платформой с одной стороны и контактным механизмом с другой, без марок.
- `node tools/make-image-prompts.js` обновляет `info/image-prompts.md`; PNG `part-pedals-2.png` генерирует пользователь в Cursor; конвертация — `python tools/convert-images.py --raw <временная папка с этим PNG>`.
- Пока файла нет, тест `every part variant has a compressed picture` красный — поэтому промпт делается первым, а вариант с картинкой коммитится вместе.
